# STC + CSK 无小车验收

状态：本机编译/测试可验证，以下物理测试仍待实机完成。不要把模拟外设测试等同于硬件已修复。

## 烧录设置

- 芯片型号按板上实际型号选择，IRC 11.0592 MHz；**P5.4设普通I/O，不能设复位脚**。
- STC与CSK独立USB供电、共地，不连接两板VCC。
- CSK A11接STC P1.0，A12接P1.1。OLED SCL接SM S1、SDA接SM S2；实际MCU分别P4.4/P4.3。
- 先运行根目录`build.bat all`。初次排查先烧`firmware/stc/build/petcargo_diagnostic.hex`，无需重烧CSK。

## 诊断固件

上电一次300ms自检音，数码管固定`12345678`，OLED为边框/条纹测试图。不会移动小车，也不会由光照、震动改变状态。

- K1短按：在固定数字与`UxxxAxxx`（命令号、导航ADC）之间切换。
- K2长按：启动/停止循环音乐；K3：立即锁定并停音乐，松开再长按解除。
- LED低三位对应K1/K2/K3，最高位对应锁定。
- USB串口9600/8N1，使用`python tools/bench_monitor.py`列出端口，再执行`python tools/bench_monitor.py COM7`（换实际端口）。不发送数据、不启动ROS。依赖pyserial，与原串口工具相同。

每500ms报告四行：

```text
K1=1 K2=1 ADC7=255 ok=1 lock=0
RX=4 F=1 E=0 O=0
raw=A55A0AF5 C=10 rej=0 M=1
ev=0/0/0/ D=0
```

K1/K2为原始电平：松开1、按下0；ADC7为原始8位值；ok为ADC有效性。RX是UART2中断收到的字节数，F是有效帧数，E是解析/超时错误，O是接收溢出次数。raw是最近4个字节；C是最后有效命令；rej=1表示唱歌被锁定拒绝，M为音乐状态。ev是各按键事件累计数，D是发送队列丢弃计数。16位诊断计数会回绕。

判断顺序：

1. `12345678`仍跑动：记录完整烧录设置及显示视频；此时与传感/OLED情绪切换无关，不能继续归咎于语音。
2. K1按下电平一直是1：核对实物按键、焊接和引脚；若电平变为0但ev不增加，记录按下/松开日志。
3. K3按下ADC应落在0–28，松开接近255；ok=0时不会按0误触发。
4. 模组回复但RX始终0：尚无串口字节到达STC。断电核对A11/P1.0及共地；可用额外3.3V逻辑USB-TTL适配器仅接RX和GND捕获A11，禁止两个TX并接或接VCC。
5. RX增加但F不增加：检查raw、波特率和E/O；正确唱歌帧必须为`A5 5A 0A F5`，不能仅发`0A`。
6. F增加、C=10但M=0：先检查lock/rej。正常未锁定时应有确认音，约500ms后开始简谱。
7. OLED只有闪烁/无测试图：先确认烧的是新映射固件及S1/S2；不会自动识别OLED是否存在（单向ULN通道不读ACK）。继续排查时不应影响数码管/按键/串口。

## 正式固件验收

诊断确认后烧`petcargo.hex`，仍保持小车断开。用户实测记录：

| 项目 | 标准 | 实测 |
|---|---|---|
| 显示 | 音乐/OLED/串口并行10分钟，无肉眼跑马灯 | 待测 |
| 按键 | K1、K2短/长按、K3锁定/解除各20次 | 待测 |
| 语音 | 12条各20次，STC命令号与行为一致 | 待测 |
| 音乐 | 1→2→3循环，降B调136 BPM；停止不自动恢复 | 待测 |
| 急停 | 正常负载K3处理并发STOP≤100ms；精确时延需仪器测量 | 待测 |
| 光照 | 19不触发；20持续200ms触发；15持续2秒重置 | 待测 |
| 离线 | 无ROS/小车、拔掉OLED均不拖慢本地功能 | 待测 |

正式固件的安全事件会停止音乐；不要通过关闭K3/震动安全逻辑来“修复”唱歌。急停优先显示STOP，可能遮住U编号；诊断固件的raw/F可独立确认命令收到与否。
